# 110 — Validation de conformité par la station

Migration préparée, non exécutée. Prérequis 107B ; conserve les protections 108/109.

- Les nouvelles lignes importées sont approuvées par la station par défaut sauf rejet explicite. Le contrôle technique du rapprochement produit/cible/usage reste distinct : seules les lignes techniquement validées d'une liste active servent à l'application.
- Rétroactivité pour les lignes déjà validées des listes non rejetées/remplacées. Aucun changement automatique des champs d'homologation ONSSA, aucune date ou valeur de sécurité fabriquée, aucun usage activé globalement.
- La confirmation accepte un usage importé validé Station sans seconde validation ONSSA manuelle. Le lien doit correspondre exactement au produit, au client, à la cible et à l'usage. Produits explicitement suspendus/retirés/expirés toujours bloqués.
- DAR source explicite (zéro seulement s'il est renseigné), délai de rentrée, dose/unité, étiquette, stock et entrepôt restent contrôlés. Chaque cause est nommée dans le message d'erreur.
- Source conservée sur l'application : entrée, liste, version, nom de fichier, date d'approbation, produit et usage.

Vérification locale : syntaxe TSX. Recette SQL à effectuer : usage Station actif complet accepté sans indicateur ONSSA manuel ; délai de rentrée absent refusé précisément ; DAR absent refusé même si un ancien import a mis zéro dans l'usage ; liste remplacée/rejetée, autre cible/client, produit retiré et stock insuffisant refusés ; voie ONSSA manuelle inchangée sans liste Station correspondante.
