# 111 — Contrôle du délai de rentrée

Préparé, migration et recette connectée à effectuer après 110.

Paramètres > Paramètres phytosanitaires, par client : « Bloquer l’application si le délai de rentrée est absent ». Activé par défaut, y compris sans ligne de paramétrage.

Modification protégée par les droits existants de paramétrage et, en SQL, par is_domain_responsible(agronomie) ou administrateur plateforme. Historique dans phyto_reentry_setting_audit (ancienne/nouvelle valeur, acteur, date).

Si désactivé, le délai absent n'empêche plus la confirmation ; avertissement JSON conservé avec le produit, l'acteur, la date et rei_hours:null dans treatment_applications.safety_warnings, affiché dans l'historique des traitements. Aucun délai source n'est remplacé par zéro. Les champs historiques de prescription ne sont pas réécrits. Une absence n'autorise pas la rentrée. Un délai renseigné inférieur à la source reste bloquant ; DAR, conformité, étiquette, stock, ferme et applicateur inchangés.

Vérification locale : syntaxe TSX. À tester en base : valeur par défaut bloquante ; désactivation par responsable et trace d'audit ; confirmation avec délai manquant et avertissement ; délai fourni toujours respecté ; réactivation sans changement des anciens avertissements ; refus utilisateur non habilité ; isolation entre clients.
